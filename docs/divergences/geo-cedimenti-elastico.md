## No divergence (same result, different implementation)
- **`strati` table origin.** Both Newmark sheets (`D7:F11` / `D15:F19`) and the T&G sheet
  (`C11:G15`) store the stratigraphy from the ground surface and derive depth-below-the-foundation-
  base bounds via `IF(B−D<0,0,B−D)` (`D`=embedment). `ground_to_base.shift_to_base` reproduces this
  exactly (including dropping any layer left with zero or negative thickness once shifted — the
  sheet's own dead rows, or a layer entirely above the embedment, behave identically: they never
  match any `z>0` lookup either way) — kept in both modes, it is the intended depth reference, not
  a bug.
- **Floating-point layer boundaries.** The sheets do this arithmetic in whole centimetres (exact in
  binary floating point); converting to SI metres (user decision D1) reintroduces the classic
  `4.80 − 1.10 == 3.6999999999999997` rounding noise, which can flip a `z`-grid point onto the wrong
  side of a `<=` layer boundary. `ground_to_base.py` and `integrate.py` round every derived depth to
  1 nm (`1e-9` m, far below any physically meaningful precision) before it reaches
  `shared.soil_layers.layer_at`; verified against the oracle fixtures (which vary `B`/`L`/embedment,
  landing grid points on different layer boundaries than the golden case).
