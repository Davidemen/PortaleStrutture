# Divergences — `strutture.geotechnics.cedimenti_edometrico`

Source: `2xxxx_Cedimenti fondazioni_elastico+edo.xlsx` (slug `geo-cedimenti`), sheet `Edometrico`
(`build/cellmaps/geo-cedimenti/edometrico.txt`). Confirmed against
`docs/specs/geo-cedimenti-edometrico.md` §"Suspected spreadsheet bugs" and
`docs/architecture-batch2.md` §7 (rows tagged `edometrico`). Golden case: B=350 cm, L=500 cm,
γ=1800 kg/mc, q=0.5 kg/cmq, D=0, 5-layer stratigraphy from `Elastico_centrale_Newmark!D7:F11`
(cached wed(f)=2.9958 cm).

| Cell | Sheet behaviour | Fixed behaviour | Clause | Numeric impact on golden case |
|---|---|---|---|---|
| `B18`/`B24:B28` | `Z,crit` ("Z per cui Δσv,q=0.1·Δσ'v") is a **plain hard-coded manual cell** (cached at 10000 cm). Cells `B24`/`B25`/`B27`/`B28` implement Cardano's formula for the cubic `Δσv,q(z)=0.1·Δσ'v(z)` (`p`, `q`, `u`, `v`) but **no cell ever assembles the root** `z=u+v−(B1+B2)/3`; the auto-derivation is dead code, and the cached value (10000 cm) is past the 5000 cm depth table, disabling the cutoff entirely. | `profondita_critica.py`: the root of `Δσv,q(z)−0.1·Δσ'v(z)=0` is solved directly by bisection (`shared.numeric.bisect`), against the **same** Δσ the tool actually integrates (`metodo_tensioni`) — not just the sheet's spread formula. The same formula is the reference stress for the (dead) `Z,crit` cubic, so a dry, embedded footing gets both a `σ'v0` column and a `Z,crit` root that are physically wrong: for γ=18 kN/m³, no water table, `D=0`, `z=5 m`, the sheet's formula gives σ'v0≈40.97 kPa instead of the true 90 kPa (review finding HIGH, `righe.py`/`profondita_critica.py`). | New optional input `falda` (depth of the water table from ground level; absent = dry site). ## No divergence (same result, different implementation)
- `M` (the sheet's `IF(z<Z,crit, K+M_prev, 0)` "reset-to-0 past cutoff, then `MAX(M:M)`" idiom):
  `righe.py`'s `cumulativo_cm` is instead an unconditional running sum for every row (like the
  sheet's own `L` column), and `cedimento.cedimento_totale` reads the cumulative value at the last
  row below `Z,crit` directly. Same numeric result (verified against the oracle case with
  `Z,crit=770 cm`, `tests/fixtures/geo_cedimenti_edometrico_oracle.json` case 3), simpler to reason
  about and to expose as a `chart`-able column (no discontinuity at the cutoff).
