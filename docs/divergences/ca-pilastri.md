## Da verificare

- **Capacity-design ductility class (γRd, `gerarchia.py`)**: this tool is documented throughout
  (`gerarchia.py`, `tool_rettangolare.py`, `tool_circolare.py`, `confinamento.py`, `dettagli.py`
  module docstrings) as targeting CD"B" columns specifically — `GAMMA_RD=1.10` and the §7.4.6.2.2
  confinement limits it applies (`STIRRUP_SPACING_MAX_BAR_MULTIPLIER=12`,
  `CONFINED_SPACING_LONG_BAR_MULTIPLIER=8`, `LONG_BAR_MAX_SPACING_SEISMIC_MM=250`) are all CD"B"
  values, not CD"A" (`γRd=1.30`, `s<=min(b0/3,125mm,6Ø)`, `ωwd>=0.12`). A reviewer flagged that
  using this tool on a CD"A" column would understate `VEd` by 18% and skip the tighter CD"A"
  detailing limits. **Not fixed**: there is no `classe_duttilita` input on either model, no
  architecture-batch2.md §9 decision authorizing one, and no oracle/golden fixture for a CD"A"
  sheet to validate against — adding one would be inventing a new input/behaviour outside this
  task's `ca_pilastri` scope (BUILD_CONTRACT: "never invent a clause"). The existing scoping is a
  documented, deliberate design decision (not a silent bug): the tool simply does not support
  CD"A" columns, and its docs say so throughout. Needs an explicit architecture decision (new
  `classe_duttilita` input + CD"A" oracle fixture) before a fix can be implemented; flagging here
  for the next architecture review rather than guessing the missing decision.
- **Confinement mechanical volumetric ratio ωwd (`confinamento.py`)**: NTC2018 §7.4.6.2.2 also
  requires `ωwd = (Vol. staffe/Vol. nucleo)·(fyd/fcd) >= 0.08` (CD"B") / `>= 0.12` (CD"A") in the
  critical zones, which this tool does not compute or check. A reviewer flagged that a column with
  widely-spaced/thin stirrups (or too few legs) can pass every existing check while violating this
  requirement. **Not fixed**: computing `ωwd` needs the number of stirrup legs and the confined
  core dimensions `b0`/`h0`, neither of which exist as inputs on either model (the original
  workbooks never computed this quantity either — there is no cell to reproduce under
  `legacy_compat=True`, so this would be a wholly new input+check, not a bug fix to an existing
  formula). Adding it is reasonable future work but requires new required/optional input fields
  (UI hints, `group`, description, `condition`) — a scope decision for architecture-batch2.md §9,
  not something to invent unilaterally here. Flagging for the next architecture review.

Every OTHER divergence above was either already confirmed by the spec/architecture docs, or
independently confirmed by direct inspection of the raw cellmap formulas cross-checked between
the two sheets (the `H9`-vs-`H16`, MIN-vs-MAX, strict-vs-inclusive comparison and gamma_Rd
findings). No item required guessing sheet intent. The `norma` columns rows above were all
confirmed by direct inspection of `build/cellmaps/ca-pilastri-ntc2018/` and
`build/cellmaps/ca-pilastri-ec2/` and by matching the recalculated oracle fixtures.

## Kept as-is (documented, not a bug)

- **cotθ "circular reference" (spec §7.4)**: the spec flags `Z13` (cotθ) as an Excel iterative
  circular reference requiring `shared.numeric.fixpoint`. Reading the raw formula graph shows
  otherwise: `sin²θ` (`CX42`) depends only on the stirrup geometry, `fyd`/`fcd` and `ac` — never on
  `cotθ`/`Z13`/`CX40` — so `Z13 = clamp(√((1-sin²θ)/sin²θ), 1, 2.5)` is a direct one-shot
  computation. Implemented as such in `taglio_theta.py` (no `fixpoint` needed); values match the
  sheet's cached cotθ exactly in both golden cases (2.5 rect / 1.98287 circ.).
- **Equivalent-square shear approximation (circular sheet)**: using a square of side `√Ac` for
  `VRdc`/`VRds` instead of a true circular-section shear model — kept in both modes per spec §7
  (not independently verified against a specific NTC/EC2 circular-column clause).
- **Cosmetic mislabel (`Z7`)**: the sheet labels the `ftk` lookup "fyk"; the value is unused
  downstream. Exposed as `MaterialiResult.ftk_non_usato_MPa` with a description noting this.
- **Dead "rettangolare" branch (circular sheet `H21`)**: `Ac = IF(G4="rettangolare", L1·L2, πD²/4)` —
  `G4` is always the fixed text `"Circolare"` on this sheet, so the branch never fires. Dropped
  entirely; `sezione_circolare` always computes `π·D²/4` (per architecture.md §6, "DROP").
- **`H23` (ρs percentage check) 3-candidate MAX(DA25:DA27) vs `J62`/`J69` (area check) 2-candidate
  aggregation**: the two rows serve different purposes (a percentage-based ceiling/floor for the
  ρs range check vs. an absolute-area minimum for the detailing check) and are kept structurally
  distinct in both modes — `rs_min` (H23) is unchanged. **Correction (review finding, CRITICAL,
  superseding the previous note here that called the `J62`/`J69` MIN aggregation itself
  "deliberate, not a bug"):** the `J62`/`J69` aggregation of its own two candidates *is* a bug —
  NTC2018 §4.1.6.1.2 requires MAX(0.003·Ac, 0.10·NEd/fyd), not MIN — now fixed under
  `legacy_compat=False` (row `J62`/`J69` above), with the sheet's non-conservative MIN kept only
  under `legacy_compat=True`.
